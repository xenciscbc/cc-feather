## 0.14.0 review state rules

Implements [the review state rules spec](specs/review-state-rules.md), recorded in [ADR 0006](adr/0006-review-state-validity-and-completion.md). Plan review, code review and outcome verification now share one review state model (`skills/delegation/references/review-state.md`). An explicitly requested pass clears a stopped step without resetting its count and lets the automatic flow resume; a user's "review" in auto is classified as automatic or explicit before dispatch; every attempted call, a generic retry included, counts; unknown state is treated as stopped; work overlapping a stopped plan keeps its stop. A pass holds only for the content it judged; plan-driven claims in the automatic flow, and claims an active handoff records as unreviewed or unverified, are reported complete only with valid APPROVED and CONFIRMED and are otherwise committed only as a labelled work-in-progress commit the user allows; and postconditions such as a release tag are checked after the operation. Main keeps ticket status current where the tracker defines a completion value, records the user's decisions by kind, does not carry counts or passing verdicts across sessions, and changes claims only with the user's authorisation. The glossary, both READMEs, ADR 0006 and amendment notes on ADRs 0004 and 0005 match. This release also includes the repository's own tracker completion values in `docs/agents/issue-tracker.md` (8cd049f), which are project configuration, not plugin behaviour. Skills, documentation and tests only; the installed policy and role definitions are unchanged, so no setup update is required, and a plugin update with a fresh session should pick up the new rules (inferred from the unchanged templates; a plugin-update-only upgrade was not exercised before release).

## 0.15.0 review follow-ups

Implements [the 0.15.0 review follow-ups spec](specs/review-followups-0-15-0.md). The delegation procedures state the review-state rules exactly: a resumed session re-reviews an unfinished plan only in auto, while unresolved verdicts recorded in an active handoff restrict work in either mode; a restriction lasts until a later call passes it or the user cancels, changes acceptance or waives, and a re-review lifts it only by passing; a claim with a postcondition has its ticket set only after the postcondition holds; a claim-changing blocker waits for the user's authorisation before it is fixed; and a waiver is never READY, APPROVED or CONFIRMED (44d6699). Both READMEs, the glossary and the 0.14.0 ADR text match (0c33429), and the contract tests guard these rules, including the older sentences whose pairings moved (7a1afa5). In auto, when review is due for implemented work whose plan has no plan-review state in this session, main now asks whether to run plan review first or go straight to code review with the missing READY waived (06c149f). The configuration tool accepts Amazon Bedrock inference-profile ARNs as role models, written unquoted, with no `---` and no trailing colon (c1f782a; spec amended in 8ffe055). Skills, documentation, tests and the configuration tool; the installed policy and role definitions are unchanged, so no setup update is required, and a plugin update with a fresh session should pick up the new rules (inferred from the unchanged templates; a plugin-update-only upgrade was not exercised before release). An older cc-feather rejects a saved ARN, so set such a role to an alias before downgrading.

Unplanned edits made on the same branch before this plan, outside the automatic review flow and not covered by this plan's reviews: handoff updates treat CommonMark ATX headings indented up to three spaces or separated by a tab as section boundaries, `.gitignore` lines are compared as Git reads them (leading whitespace kept), and a blank work title is a format problem (de7562a); the setup link test records a dangling symlink instead of reading through it, which failed on POSIX (d61b03b).
