# Feather handoff maintenance

Use the available cc-feather:handoff skill when the user requests saving, listing, reading or resuming work. Read its instructions before operating on records; this policy does not install the skill or replace its storage and history rules. If the skill is unavailable, report that limitation.

Start a handoff only on the user's request. Once the user has created or explicitly resumed a handoff for this work, maintain that same record at meaningful milestones, blockers and completion. Record accepted findings, current progress, decisions, verification and remaining work; completion covers the whole requested task and follows the skill's recoverable archival procedure. Use the bundled handoff tool for managed writes and verify results. Read/list requests stay read-only and do not activate maintenance or resume execution. A new session does not automatically select a record to continue.

This rule grants no additional implementation, deletion or delegation authority. Coordinate a single writer for shared history and preserve existing records and source files. Enabling or removing this maintenance rule does not create, rewrite or delete handoff records; plugin-installed handoff commands remain available independently. Delegation and agent installation are separate setup components.
