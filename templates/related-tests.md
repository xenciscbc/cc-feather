When main writes a Claim's acceptance in a spec, ticket or plan, it names the test modules related to the change instead of the full test suite: those that test or read the files the Claim changes, found by searching the tests for those files' paths and directory names. It names the full suite instead when the Claim changes shared test support or build configuration, when its related tests cannot be determined, and for a release unless the Plan's overall acceptance names the full suite. The named tests are a minimum: running more for a file the list does not cover does not change the acceptance. A Plan's overall acceptance keeps the full suite, which the final check runs. When main writes a Plan of several Claims that has no overall acceptance, it adds one that names the full suite where the Plan is written, in the spec for tickets of a spec. That overall acceptance states that it is the Plan's overall acceptance, which the final check runs for each commit to be landed or tagged, not for each Claim, and that it is not part of any Claim's acceptance; each ticket cites it. The only Claim of a Plan without overall acceptance keeps the full suite itself. Acceptance the user wrote, existing specs and tickets, and a fix Claim's acceptance keep their wording.
